Case File / Harness Evidence

agent-recall

跨 AI coding agent、工具、项目和会话的持久记忆与连续性案例。

Memory case-study GitHub repo

Problem

AI coding agent 会在会话之间失忆，也会在不同工具之间形成记忆孤岛。用户被迫成为所有工具之间的 memory bus。

Why It Matters

真正的 Agent 产品需要知道用户是谁、项目是什么、当前任务进展到哪里、哪些事实应保留在项目内、哪些知识应提升为全局记忆。

Product Thesis

Agent memory 不是聊天记录，而是跨工具、跨 session、跨项目、跨用户画像、persona、active task 和 retrieval 的结构化连续性。

My Role / Judgment

核心判断是把 memory 语义从单一 Agent host 中抽出来，让不同工具共享同一套 memory infrastructure。

Architecture

结构包括：

  1. 多平台 adapter：Claude Code、Cursor、Codex CLI、Gemini CLI、OpenCode。
  2. 本地 worker HTTP API。
  3. persona、bootstrap、recovery、memory layering、promotion、archives 和 search。
  4. SQLite / FTS 存储，可选 vector search。

Design Tradeoffs

我选择结构化 summary，而不是直接把 transcript 当作记忆；选择 global / project 分层和 promotion policy，避免记忆变成噪声。

What I Built

  • 跨多个 coding agent 的共享记忆。
  • tool execution hook 捕获。
  • AI 压缩观察结果。
  • session start 上下文注入。
  • persona / user profile bootstrap。
  • active task recovery。
  • memory promotion 和 searchable archives。

Evidence

公开 repo 描述了共享 SQLite、多平台 adapter、worker API、persona/bootstrap/recovery、memory layering、promotion、archives 和 search。

What I Learned

Memory 质量主要是产品问题：捕获什么、何时压缩、注入什么、何时提升、如何避免过期上下文污染新任务。

Status

Alpha / usable prototype。

Next

下一步是评估 memory 注入是否真正帮助 Agent 恢复任务、减少重复错误，并保留用户和项目偏好。
