Case File / Harness Evidence

agent-guard

位于模型循环之外的确定性 Agent 安全与控制层案例。

Security / Control case-study GitHub repo

Problem

prompt 规则不是控制系统。真正重要的安全规则不能只靠模型记住和自觉遵守。

Why It Matters

真实 Agent 产品需要能行动，也需要访问文件、终端、工具、密钥和 workflow。产品问题不是把 Agent 关死，而是在允许有用工作的同时卡住不可逆风险。

Product Thesis

安全应该在执行管线里，而不是在 Agent 的自我描述里。Agent 可以提出动作，但敏感动作必须经过模型无法绕过的确定性门禁。

My Role / Judgment

我的核心判断是从 prompt-based safety 转向 hook-based control。hook 看到真实 tool call，模型不能和它讨价还价。

Architecture

agent-guard 通过 Claude Code PreToolUse / PostToolUse hooks 工作。

五层引擎：

  1. hard rules。
  2. path safety。
  3. trust evaluation。
  4. rate anomaly。
  5. synthesis。

PostToolUse 还会做 credential sanitizer。

Design Tradeoffs

我选择低延迟、确定性的本地 gate，而不是把所有风险都交给重模型判断。正常路径必须足够便宜，危险路径必须足够清楚。

What I Built

  • hook-based tool call interception。
  • 5-layer decision engine。
  • 32 built-in rules。
  • credential sanitization。
  • trust、audit、rule management 和配置命令。

Evidence

公开 repo 描述了 deterministic security interception layer、5-layer Swiss Cheese engine、32 built-in rules、zero dependencies 和低延迟 pipeline。

What I Learned

Agent 安全不是“全部阻止”，而是在保留有用自治的同时，让危险转移变得确定、可见、可审计。

Status

Prototype / usable security layer。

Next

下一步是更广 agent host 支持、更强 false positive 分析，并与 SkillScanner 这类 supply-chain review 结合。
