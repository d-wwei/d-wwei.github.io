Case File / Harness Evidence

SkillScanner

Portable pure-instruction scanner for skill, MCP, and prompt-level Agent supply-chain risk.

Security / Skills case-study GitHub repo

Problem

Agent skills and MCP tools create a new supply-chain surface. A skill can carry hidden instructions, tool poisoning, exfiltration logic, encoded payloads, or social engineering that targets the host Agent rather than the human reader.

Most scanners assume code dependencies, models, or a specific runtime. But skills are often just instruction files that need to work across many Agent hosts.

Why It Matters

As Agent ecosystems grow, skills can spread like packages. The risk profile begins to look like early npm, except the exploit language is not only code. It can be prompt text, metadata, tool descriptions, MCP payloads, or memory manipulation.

A practical harness needs a portable scanner that can be installed into different Agent hosts and understand language-level threats, not just code signatures.

Product Thesis

The scanner itself can be a skill.

If an Agent host can read SKILL.md, then a security scanner can be delivered as a pure instruction protocol. The host Agent becomes the semantic detection engine, while the skill supplies threat taxonomy, gates, scoring, and reporting discipline.

My Role / Judgment

The key product judgment was portability over dependency depth. A scanner that requires a large model download or language-specific setup will not protect lightweight agent workflows.

The second judgment was to treat semantic detection as a first-class layer. Regex catches some attacks, but prompt-level threats often evade keyword matching by rephrasing intent.

Architecture

SkillScanner is a single SKILL.md plus reference files.

The scanning protocol has five layers:

  1. Normalize content and decode obfuscation.
  2. Match known threat categories.
  3. Run semantic intent and structural archetype analysis.
  4. Judge local context and false-positive dampening.
  5. Produce a bucket-weighted risk verdict.

It also defines three gates: input, tool-result, and output. That matters because indirect injection often arrives through tool results, not initial user input.

Design Tradeoffs

I chose pure instructions and no dependencies. That makes the scanner portable and easy to install, but it means quality depends on the host Agent’s reasoning ability and the precision of the protocol.

To compensate, the scanner uses layered evidence, explicit categories, OWASP tags, per-finding context judgment, and structured reporting. The protocol is the product.

What I Built

  • A portable security scanner delivered as SKILL.md.
  • Reference files for scan protocol, threat catalog, attack cases, report templates, and self-tests.
  • 10 threat categories covering prompt injection, context manipulation, MCP tool poisoning, exfiltration, dangerous operations, metadata poisoning, and memory/state poisoning.
  • A 3-gate scanning model across input, tool-result, and output.
  • A 5-layer scan protocol with bucket-weighted risk scoring.
  • Bilingual EN/ZH usage.

Evidence

The public repo describes SkillScanner as a universal AI agent skill security scanner with no dependencies and bilingual EN/ZH support. The README documents the 5-layer protocol, 3-gate architecture, 10 threat categories, structural archetypes, and risk scoring.

The project is intentionally not a small command-line wrapper. It is an experiment in whether security capability can itself be packaged as a governed Agent skill.

What I Learned

Agent supply-chain security needs to reason about intent, not just syntax. A malicious skill can look like documentation, a tutorial, a tool description, or a harmless helper until the host Agent treats it as instruction.

The harness layer should review skills before installation, during tool-result ingestion, and before final output when leakage or compromised behavior is possible.

Status

Prototype / portable scanner. It is useful as a skill-security concept and working protocol, but should be tested against larger real-world skill and MCP corpora before being treated as production-grade.

Next

The next step is to connect SkillScanner with runtime control layers such as agent-guard, add corpus-level evaluation, and create clearer governance workflows for installing, updating, and rejecting Agent skills.
